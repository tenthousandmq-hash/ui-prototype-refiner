# ui-typography-governance (排印与阅读人体工学治理)

面向专业设计师与工程流水线的文本视觉工程基线。
排除了任何主观审美形容词，将文本排版彻底转化为**眼动工学安全底线、双轨功能分类与跨平台系统字体工程标准**。

---

## 一、 系统字体栈与双轨功能分类

### 1. 跨平台系统字体栈声明（System Font Stack）
国内 Web/客户端生产环境严禁依赖体积庞大的网络字体包，统一声明跨平台高表现力系统字体降级栈：
```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", "PingFang SC", "Microsoft YaHei", sans-serif;
```

### 2. 双轨功能分类（Dual-Track Functional Roles）
文本排印必须基于**功能本质**解耦为两条并行轨道，严禁通篇混用单一的字号或行高逻辑。**（注：本规范仅定义功能本质与物理约束，严禁机械套用固定模板）**：

#### 轨道 A：`Body`（内容阅读轨）
* **功能本质**：用于承载需要连续、沉浸式眼动阅读的多行文本场景。
* **物理治理目标**：
  * **阅读工学防疲劳**：必须留足回行缓冲，行高根据字号采用舒展倍率（$1.50 \sim 1.65$）；
  * **单行行长受控（Measure）**：多行连续文本容器必须受 `max-width: 65ch` 限制，防止宽屏下横向拉通造成找行困难；
  * **字重克制**：以基准字重（Regular 400）为主，严禁在大段长文中大面积使用重字重，防止产生墨块压迫感；
  * **基准尺寸弹性**：结合界面信息密度需求自主决策（高密场景选用 14px，宽松长文场景选用 16px）。

#### 轨道 B：`Label`（交互控件轨）
* **功能本质**：用于承载界面操作逻辑、状态提示、功能导航与数据标记的短文本场景。
* **物理治理目标**：
  * **空间紧凑与形态自洽**：文本通常为单词或短语，随容器组件自适应包裹，不受 65ch 行宽限制；
  * **多层次字重与字号**：根据控件本身的视觉主次（主行动、常规选项、辅助弱提示），在 400（常规）与 600（强调）之间阶梯式选用，严禁对控件区全量统一加粗；
  * **网格对齐**：行高严格吸附 4px 乘数，确保控件外盒模型与全局网格严密咬合。

## 二、 核心量化底线（Linter Hard Gates）

流水线仅拦截以下**破坏体验的客观物理硬伤**，其余排版自由度完全保留给系统自适应与设计师裁决：

```
                    【流水线客观拦截边界】
                              │
     ┌────────────────┬───────┴────────┬────────────────┐
     ▼                ▼                ▼                ▼
【Measure 逃逸】   【行高过紧】      【网格错位】     【非标字阶】
单行超 75 字符     连续文本行高      行高非 4 乘数    出现浮点数(如13.5px)
大屏拉通无限制     低于 1.35x       导致像素抖动     或随意手写奇数字号
```

### 1. 4px 乘数固定行高模数（Fixed Line-Height）
摒弃不可控的随机浮点行高，所有计算后的行高必须整除 **4px**（如 16px, 20px, 24px, 32px），使文本外边框天然咬合 4px/8px 空间网格。

### 2. 汉字行高安全底线
由于中文字面率高达 85%~92%，多行连续文本的行高严禁低于 **1.35 倍**，防止汉字笔画上下粘连形成黑色墨斑。

### 3. 黄金行长上限（Measure）
连续多行文本容器必须设置 `max-width: 65ch`（约 640px~760px / 30~45 汉字），在桌面大屏视口下严禁随父容器无限拉伸。

### 4. 垂直节拍（Vertical Rhythm）
段落间距使用相对单位 `margin-block-end: 0.85em`，确保段间留白显著大于行距，建立清晰的段落边界。

## 三、 三阶段工作模式契约

### 模式 1：`--mode=diagnostic`（事前排查 / 截图初评）
* **定位**：纯只读静态分析器。**严禁修改任何代码。**
* **机检项目**：
  1. 扫描长文文本容器是否缺失 65ch 宽度上限；
  2. 扫描是否出现脱离通用字阶的非标字号（如 13.5px 浮点）；
  3. 扫描多行正文行高是否低于 1.35；
  4. 扫描行高是否偏离 4px 乘数。
* **输出**：结构化的《排印病灶清单》。

---

### 模式 2：`--mode=patch`（设计执行 / 规范化补丁）
* **定位**：原子级补丁生成器。
* **执行逻辑**：
  1. 在全局 CSS 注入双轨变量基础骨架：
     ```css
     :root {
       --font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", "PingFang SC", "Microsoft YaHei", sans-serif;
       
       /* 内容阅读轨 (Body) */
       --body-font-size: 14px;          /* 结合密度可弹性设为 14px 或 16px */
       --body-line-height: 20px;        /* 对应 20px 或 24px，整除 4px */
       --body-measure: 65ch;
       
       /* 交互控件轨 (Label) */
       --label-font-size: 14px;
       --label-line-height: 20px;
       --label-font-size-sm: 12px;
       --label-line-height-sm: 16px;
     }
     ```
  2. 针对多行长文容器注入 `max-width: var(--body-measure)` 与安全行距；
  3. 针对控件文本注入吸附 4px 的固定行高，字重按交互层级克制分配；
  4. 消除所有浮点与非标字号。

---

### 模式 3：`--mode=verification`（事后审核 / 终审门禁）
* **定位**：交付前客观硬红线闸门。
* **执行逻辑**：静态走查是否存在 Measure 逃逸、极端行高挤压或浮点字号。
* **主观裁决移交**：界面的具体字阶搭配、气场契合度与视觉美感，**100% 移交设计师肉眼终审**。
