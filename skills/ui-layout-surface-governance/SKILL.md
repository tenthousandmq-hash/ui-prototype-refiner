# ui-layout-surface-governance (空间网格与表面色彩安全治理)

面向专业设计师与工程流水线的容器布局与视觉表面工程基线。
通过**空间几何语义化**与**先墨后纸色彩安全锁**，彻底解决自动化界面设计中常见的“奇数边距混乱、圆角挤压变形、盲目调色砸出突兀灰脏补丁、规范自相矛盾导致数值死锁”等工程痛点。

---

## 一、 空间几何常数与间距语义化架构

本系统严禁在组件内部硬编码散落的像素数值，所有间距必须遵循**“M3 百进制标尺 $\to$ 关系几何语义指针 $\to$ 组件零像素消费”**三层解耦。

### 1. M3 百进制空间量子标尺 (Baseline Quantum Scale)
以 **8px 为系统基准量子**（$1.0\times = 8\text{px} = \text{space-100}$），底层仅提供严格整除的离散常数池，严禁出现奇数或 Subpixel 浮点数：

```css
:root {
  --space-25:  2px;   /* 0.25x: 极限微调、发丝线对齐 */
  --space-50:  4px;   /* 0.50x: 原子微间隙、图标与文字内联 */
  --space-75:  6px;   /* 0.75x: 紧凑型输入框与标签微补 */
  --space-100: 8px;   /* 1.00x: 系统基准量子 (Base Unit) */
  --space-150: 12px;  /* 1.50x: 控件内衬、次级卡片内隙 */
  --space-200: 16px;  /* 2.00x: 标准卡片间隙 (Grid Gap)、内容段落垂直流 */
  --space-300: 24px;  /* 3.00x: 容器标准内边距 (Padding)、卡片领地缓冲 */
  --space-400: 32px;  /* 4.00x: 独立功能区块间距、页面子模块分界 */
  --space-600: 48px;  /* 6.00x: 页面级大外壳留白、主段落分界 */
}
```

### 2. 关系几何与语义插槽 (Relational Geometry Slots)
落实格式塔知觉心理学 4 大关系定律，全站组件**仅允许引用以下 5 个语义插槽**：

| 语义插槽 (Token) | 默认装配值 | 对应的格式塔法则与物理含义 |
| :--- | :--- | :--- |
| `--gap-atomic` | `var(--space-50)` (4px) | **定律 1：原子强内聚**。图标+文字、Badge 微标签内部。 |
| `--gap-sibling` | `var(--space-100)` (8px) | **定律 1：兄弟弱相关**。标题+正文、输入框 Label+Input。 |
| `--gap-flow` | `var(--space-200)` (16px) | **定律 1：并列流向**。卡片并列 Gap、正文段落纵向间距。 |
| `--pad-card-y` | `var(--space-200)` (16px) | **定律 2 & 3：非对称领地**。垂直缓冲（压缩优先区）。 |
| `--pad-card-x` | `var(--space-300)` (24px) | **定律 2 & 3：领地包容**。水平缓冲（保证 $\text{Padding} \ge \text{Internal Gap}$）。 |
| `--gap-section` | `var(--space-400)` (32px) | **定律 4：图底呼吸底线**。跨功能独立大区块分隔。 |

> [!CAUTION] 组件层零像素原则 (Zero-Pixel in Components)
> 在各组件选择器（如 `.card`, `.btn`, `.item`）内部，**绝对禁止出现具体的 `16px`、`24px` 等硬编码字样**；必须全量绑定语义插槽。

### 3. 运行时密度调度 (Density Modifiers)
系统通过 CSS 属性选择器的树状作用域就近覆盖，实现全局或局部容器的一键密度缩放，无需 JS 介入，杜绝半像素模糊：

```css
/* Level -1: 紧凑档位 (Compact) - 垂直轴定向等差压缩 4px，微间隙触底保底 */
[data-density="compact"], [data-density="-1"] {
  --gap-atomic:  var(--space-50);   /* 4px 触底保底 */
  --gap-sibling: var(--space-75);   /* 6px */
  --gap-flow:    var(--space-150);  /* 12px (-4px delta) */
  --pad-card-y:  var(--space-150);  /* 12px (-4px vertical compression) */
  --pad-card-x:  var(--space-200);  /* 16px (-8px horizontal compression) */
  --gap-section: var(--space-300);  /* 24px (-8px delta) */
}

/* Level +1: 舒展档位 (Spacious) */
[data-density="spacious"], [data-density="1"] {
  --gap-atomic:  var(--space-75);   /* 6px */
  --gap-sibling: var(--space-150);  /* 12px */
  --gap-flow:    var(--space-300);  /* 24px */
  --pad-card-y:  var(--space-300);  /* 24px */
  --pad-card-x:  var(--space-400);  /* 32px */
  --gap-section: var(--space-600);  /* 48px */
}
```

### 4. 嵌套同心圆角法则与组件级下沉声明 (Concentric Nested Radius)
* **几何定理**：当一个带圆角的子元素嵌套在带圆角的父容器中时，为保持视觉边距厚度均匀，内外圆角必须同心：
  $$R_{\text{inner}} = \max(R_{\text{outer}} - \text{Padding}, \text{保底微弧 } 4\text{px})$$
* **下沉声明铁律（防作用域求值固化）**：
  * **严禁在 `:root` 声明静态复合衍生变量**（如 `--radius-inner: calc(...)`），否则在运行时切换密度（`compact`）或面对不同内衬的父容器时，CSS 变量继承会导致内圆角数值脱钩失效；
  * **必须直接将原生数学公式注入被嵌套组件的选择器属性上**：
    ```css
    .status-badge {
      /* 原生表达式下沉：动态捕获局部生效的 Padding 与外圆角 */
      border-radius: max(var(--space-50), calc(var(--radius-card) - var(--pad-card-x)));
    }
    ```
* **容器高度弹性原则**：严禁在带 Padding 的容器上写固定 `height: xx px`，必须统一采用 `min-height` 或完全交由 `padding + content` 自然支撑。

## 二、 核心色彩与表面安全锁（Surface & Color Defense）

为杜绝“规则满足了但画面变丑、局部调出突兀黑脏色块”的恶性翻车，本 Skill 确立**“先冻纸面，后调墨色”**的刚性执行时序与四道不可突破的防线：

```
       【输入待治理界面 / 粗糙原型】
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【阶段一：定纸 (Surface Freeze)】                      │
│ 确立底板与主卡片，剔除脏灰色块；静态表面锁定 ΔL <= 3%    │
└───────────────────────┬────────────────────────────────┘
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【阶段二：调墨 (Text Tuning / APCA)】                  │
│ 纸张绝对不动，仅调文本 Token 满足 APCA 75 / 60 / 45    │
└───────────────────────┬────────────────────────────────┘
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【阶段三：控件与焦点核验 (Control & Focus)】           │
│ 控件文本满足 APCA Lc >= 60；保留 :focus-visible 轮廓线 │
└────────────────────────────────────────────────────────┘
```

### 防线 1：调墨不调纸（Text First / Surface Freeze）
* **病理原理**：文本像素覆盖率 $< 5\%$，调整文本明度对全屏灰度平衡近乎零冲击；而重涂大面积背景色（覆盖率 $> 60\%$）会瞬间摧毁页面的产品调性、视觉极性与整体光感。
* **刚性执行顺序**：
  1. **先定纸**：底盘与主卡片背景色一旦确立（体现产品核心调性），**100% 绝对冻结**；
  2. **后调墨（调整文本属性）**：当检测到文本可读性不满足 APCA 时，**严禁通过改动卡片底色或擅自添加背景色块来凑对比度**；必须在冻结的底盘上，通过调整文本自身的属性（颜色 Token、字号或字重）来达成 APCA 规范。

### 防线 2：静态表面低 Delta 约束（Low Delta Surfaces, $\Delta L \le 3\%$）
* **适用范围声明（概念解耦）**：
  * **本规则仅严格约束“静态大面积布局容器（Surfaces）”**，包括主底板、工作大岛（Island）、内容卡片（Card）与分栏底色；
  * 嵌套卡片、内部面板与主背景之间的明度差（Lightness Delta）**严禁超过 3%**，严禁使用高明度差的深色实底色块充当静态容器。
* **交互控件（Controls）的独立核验原则**：
  * 按钮、Badge、输入框属于实体交互构件，**不属于大面积静态表面，不受 3% 规则约束**；
  * 交互构件不限制具体的 Token 命名，仅在校验阶段使用 APCA 规则核验：控件前景文字相对于控件自身背景实测满足 $L_c \ge 60$ 即可；
  * 交互动态反馈（Hover / Active）优先通过边框对比度强化、文字明度加深或聚焦轮廓线承载，保持底板纸面克制。

### 防线 3：静态边界界定优先与交互焦点保护（Static Separation & Focus Freeze）
* **静态容器界定优先次序**：
  1. **首选**：大尺度负空间留白（`gap: var(--gap-flow)` 或 `var(--gap-section)`）；
  2. **次选**：符合设计系统的 1px 低透明度微边框；
  3. **绝对禁止**：依靠高对比度的深浅大色块强行拼接容器。
* **保留交互聚焦轮廓线（Focus Indicator Protection）**：
  * **严禁消除交互聚焦轮廓**：交互控件在 `:focus`、`:focus-visible` 状态下必须保留清晰可见的键盘聚焦指示轮廓（`outline`）；
  * **绝对禁止**在交互控件上使用 `outline: none` 或将其弱化为不可见。

### 防线 4：纯化 APCA 文本层级感知阶梯（Hierarchy Step Model & Single Standard）
* **单一标准确立（彻底废除 WCAG 2.1 4.5:1 平铺比值）**：
  * 鉴于 WCAG 2.1 脱离字号导致三级辅助文案与一级标题打架产生数值死锁，**全系统统一采用 W3C WCAG 3.0 APCA 感知算法作为唯一权威判定标准**；
  * APCA 联立计算字号、字重与感知对比度（$L_c$），建立健康、呼吸的层级梯队：

  ```
  [一级：标题 / 核心数据]  ──( ΔLc >= 15 )──>  [二级：正文 / 控件文本]  ──( ΔLc >= 15 )──>  [三级：说明 / 辅助信息]
  ```

  | 文本层级 | 业务职能 | $L_c$ 生理底线 | 相对层级阶差（$\Delta L_c$） | 字号物理红线 |
  | :--- | :--- | :--- | :--- | :--- |
  | **一级 (Primary)** | 卡片标题、核心焦点数值 | $L_c \ge 75$ | 基准最高级 | 推荐 $\ge 16\text{px}$ |
  | **二级 (Secondary)** | 正文阅读、表单 Label、常规按钮 | $L_c \ge 60$ | 与一级差值 $\Delta L_c \ge 15$ | 推荐 $13 \sim 15\text{px}$ |
  | **三级 (Tertiary)** | 辅助说明文案、路径脚注、辅助图标 | **$L_c \ge 45$** | 与二级差值 $\Delta L_c \ge 15$ | **刚性红线：严禁低于 12px** |

* **防代偿风控铁律**：*严禁为了盲目拉大层级差值（$\Delta L_c$），而把三级辅助文字明度无限压低。* 只要三级文本字号 $\ge 12\text{px}$ 且 $L_c \ge 45$，即满足人类视网膜可读性底线，禁止过度加黑破坏视觉色温。
* **主观审美终审权**：界面的色温、质感、气场与整体情绪，**裁决权 100% 移交给人类设计师肉眼**。

## 三、 三阶段工作模式契约

### 模式 1：`--mode=diagnostic`（事前排查 / 截图初评）
* **定位**：纯只读静态分析器。*严禁修改任何代码。*
* **输入**：前端代码文件、CSS 样式表，或界面截图。
* **执行逻辑**：
  1. 扫描盒模型中逃逸出语义 Token 的非标硬编码像素（检查是否违反零像素原则）；
  2. 扫描嵌套卡片内外圆角是否出现同尺寸挤压（检查是否未下沉同心公式）；
  3. 扫描静态大面积表面是否存在明度差 $>3\%$ 的突兀脏灰实底色块；
  4. 检查各级文本是否满足 APCA 层级阶差（$\Delta L_c \ge 15$）与三级字号底线（$\ge 12\text{px}$）。
* **输出**：结构化的《空间与表面病灶清单》。

---

### 模式 2：`--mode=patch`（设计执行 / 规范化补丁）
* **定位**：原子级补丁生成器。在**空间语义化与先墨后纸安全锁**双重约束下生成微型 Diff。
* **输入**：确认需要修复布局/表面缺陷的目标文件。
* **执行逻辑**：
  1. **间距语义化注入**：
     * 在 `:root` 挂载百进制标尺（`--space-25` 到 `--space-600`）与 5 大语义插槽；
     * 将组件内部所有 `padding`、`margin`、`gap` 硬编码像素替换为语义 Token 指针（`--gap-*`, `--pad-*`），实现组件层零像素；
     * 挂载 `[data-density="compact"]` 与 `[data-density="spacious"]` 调度规则；
  2. **同心圆角组件级重构**：直接在被嵌套组件的 `border-radius` 上注入原生公式 `max(var(--space-50), calc(var(--radius-outer) - var(--pad-container-x)))`，严禁包在 `:root`；
  3. **色彩与表面安全修复**：
     * **定纸**：背景底板与主卡片保持不动（冻结）；清除明度差超过 3% 的突兀实底色块，转换为与主底板同色或采用微发丝线界定；
     * **调墨**：在冻结纸面上，通过调整文字 Token 或字号字重满足 APCA $75 / 60 / 45$ 阶梯；三级字号补齐至 $\ge 12\text{px}$；
     * **控件与焦点**：交互控件内文本满足 APCA $L_c \ge 60$，保留清晰可见的 `:focus-visible` 轮廓线（严禁 `outline: none`）。
* **交付物**：Git 风格原子差异补丁（Diff）。

---

### 模式 3：`--mode=verification`（事后审查 / 终审门禁）
* **定位**：交付前客观硬红线闸门与只读数据辅助。
* **执行逻辑**：静态走查以下硬伤：
  * [ ] 组件内部是否违规残留非 Token 硬编码间距像素（组件零像素机检）；
  * [ ] 嵌套组件是否正确下沉了同心圆角动态公式（严禁内外同大角）；
  * [ ] 容器高度是否弹性化（严禁写死 `height` 导致密度压缩被截断）；
  * [ ] 静态大面积表面是否出现明度差 $>3\%$ 的突兀脏灰实底（$\Delta L \le 3\%$ 机检）；
  * [ ] **APCA 纯化单轨审查**：一/二/三级文本是否全量达标（$L_c \ge 75 / 60 / 45$，$\Delta L_c \ge 15$），三级字号是否 $\ge 12\text{px}$；
  * [ ] 交互状态是否保留清晰可见的聚焦轮廓线（严禁 `outline: none`）；
* **主观裁决移交**：界面的整体空间疏密呼吸感、光感质地与品牌契合度，**直接移交设计师肉眼终审**。
