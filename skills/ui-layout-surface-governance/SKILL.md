# ui-layout-surface-governance (空间网格与表面色彩安全治理)

面向专业设计师与工程流水线的容器布局与视觉表面工程基线。
通过几何常数与**刚性色彩安全锁**，彻底解决自动化界面设计中常见的“奇数边距混乱、圆角挤压变形、盲目调色砸出突兀灰脏补丁”等工程痛点。

---

## 一、 空间几何常数与数学公式

### 1. 8-Point / 4-Point 空间标尺
* **行业依据**：Bryn Jackson 8-Point Grid System
* **数学硬红线**：所有容器的 `padding`、`margin`、`gap`、`height` 必须严格整除 **4px**（首选 8px 倍数）：
  $$\text{Dimension} \in \{4, 8, 12, 16, 20, 24, 32, 40, 48, 64\}\text{px}$$
* **拦截项**：禁止手写 `7px`, `9px`, `13px`, `15px`, `22px` 等非标间距或 Subpixel 浮点数。

### 2. 嵌套同心圆角法则（Concentric Nested Radius）
* **几何定理**：当一个带圆角的子元素嵌套在带圆角的父容器中时，为保持视觉边距厚度均匀，内外圆角必须同心：
  $$R_{\text{inner}} = \max(R_{\text{outer}} - \text{Padding}, 0)$$
* **保底微弧**：当 $\text{Padding} \ge R_{\text{outer}}$ 时，计算结果为 0px（产生尖锐直角）。为消除生硬感，必须对内层赋 `2px ~ 4px` 的保底软微弧，严禁内外层写死相同的大圆角。

### 3. 格式塔外斥内聚律（Proximity Separation）
* **排版物理学**：同级组间外斥间距必须显著大于组件内部内聚间距：
  $$\text{Gap}_{\text{outer}} \ge 1.5 \sim 2.0 \times \text{Gap}_{\text{inner}}$$
* **拦截项**：卡片内部的组件间距如果大于卡片与卡片之间的间距，即构成视觉结构坍塌。

## 二、 核心色彩安全锁（Color Governance Defense）

为杜绝“规则满足了但画面变丑、局部调出突兀黑脏色块”的恶性翻车，本 Skill 强制执行**三道不可突破的色彩防线**：

```
       【检测到局部对比度不足 或 边界粘连】
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【防线一：调墨不调纸 (Text-First)】                     │
│ 优先压低文字明度 (调墨)；严禁改变大面积背景色 (纸)！     │
└───────────────────────┬────────────────────────────────┘
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【防线二：低 Delta 表面约束 (Delta L <= 3%)】          │
│ 容器与底板明度差严禁超过 3%，杜绝深浅大色块硬拼          │
└───────────────────────┬────────────────────────────────┘
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【防线三：边界界定优先法则】                             │
│ 负空间留白 (16~24px) > 1px 半透明发丝线 > 严禁纯色块拼接  │
└────────────────────────────────────────────────────────┘
```

### 防线 1：调墨不调纸（Text First / Surface Freeze）
* **病理原理**：文本像素覆盖率 $< 5\%$，调整文本明度对全屏灰度平衡近乎零冲击；而容器背景覆盖率 $> 30\%$，调整背景会导致画面产生巨大视觉黑洞。
* **工程铁律**：**当文字与背景对比度不足时，绝对禁止通过调暗/调亮大面积容器背景来凑对比度！**
  * 必须且仅允许将前景文字 Token（如 `text-muted`）的明度下潜加深，直至满足 WCAG 4.5:1 基线。底板容器背景在此阶段绝对冻结。

### 防线 2：低 Delta 表面阶梯（$\Delta L \le 3\%$）
* **工程铁律**：浅色模式下，同视口内相邻表面（如 Canvas 画卷与 Card 卡片）的明度差严禁超过 **3%**。
  * 若画卷底色为 `#faf9f5`，卡片表面仅允许在 `#f2efe6` ~ `#ffffff` 范围内微调；
  * 严禁为了突出卡片，直接套用 `#e5e5e5` 或 `#dcdcdc` 的灰泥巴底色。

### 防线 3：留白与发丝线优先，色块拼贴垫底
* **工程铁律**：定义容器边界的优先级次序：
  1. **首选**：大尺度负空间留白（`gap: 20px~24px`）；
  2. **次选**：1px 极低透明度发丝线（如 `border: 1px solid rgba(0, 0, 0, 0.08)`）；
  3. **绝对禁止**：依靠高对比度的大面积深浅色块强行拼贴。

## 三、 三阶段工作模式契约

### 模式 1：`--mode=diagnostic`（事前排查 / 截图初评）
* **定位**：纯只读静态分析器。**严禁修改任何代码。**
* **输入**：前端代码文件、CSS 样式表，或界面截图。
* **执行逻辑**：
  1. 扫描盒模型中逃逸 4px 乘数的非常规间距；
  2. 扫描嵌套卡片内外圆角是否出现同尺寸挤压；
  3. 扫描三栏或多卡片是否存在表面极性平坦化（无层级）或突兀脏色块；
  4. 检查文本与背景的 WCAG 对比度（AA 级 $\ge 4.5:1$）。
* **输出**：结构化的《空间与表面病灶清单》：
  ```markdown
  ### [ui-layout-surface-governance] 诊断报告
  - [硬伤] 发现 6 处边距逃逸：`.sidebar` padding: 7px, `.card` margin: 15px，未对齐 4px 标尺。
  - [硬伤] `.outer-card (r=16px)` 内嵌套 `.inner-box (r=16px)`，内角挤压变形，违背同心圆角法则。
  - [硬伤] 辅助文字 `#999` 在 `#f5f5f5` 底色上对比度仅 2.3:1，未达 WCAG 4.5:1 AA 级红线。
  - [警告] 主画卷与卡片背景色完全同化，边界缺乏发丝线或负空间界定。
  ```

---

### 模式 2：`--mode=patch`（设计执行 / 规范化补丁）
* **定位**：原子级补丁生成器。在**色彩安全锁**约束下生成微创 Diff。
* **输入**：确认需要修复布局/表面缺陷的目标文件。
* **执行逻辑**：
  1. **间距归一化**：将所有非常规间距强制就近吸附至 4px 乘数变量（如 7px $\to$ 8px, 15px $\to$ 16px）；
  2. **同心圆角重构**：自动注入公式 `border-radius: calc(var(--parent-radius) - var(--padding))`，或保底软微弧 `4px`；
  3. **色彩安全修复**：
     * 背景色绝对保持不动（冻结）；
     * 将低对比度文字映射至符合 WCAG 标准的加深 Token；
     * 将粗重黑框替换为 `1px solid rgba(0, 0, 0, 0.06 ~ 0.08)` 暖/冷发丝线。
* **交付物**：Git 风格原子差异补丁（Diff）。

---

### 模式 3：`--mode=verification`（事后审核 / 终审门禁）
* **定位**：交付前客观硬红线闸门。
* **执行逻辑**：静态走查以下硬伤：
  * [ ] 是否残留奇数像素边距；
  * [ ] 是否出现明度差 $>5\%$ 的突兀脏灰卡片块（防突兀视块机检）；
  * [ ] WCAG AA 级对比度是否全量达标（$\ge 4.5:1$）；
* **主观裁决移交**：界面的整体空间疏密呼吸感、光感质地与品牌契合度，**直接移交设计师肉眼终审**。
