# ui-layout-surface-governance (空间网格与表面色彩安全治理)

面向专业设计师与工程流水线的容器布局与视觉表面工程基线。
通过**空间几何语义化**与**先墨后纸色彩安全锁**，彻底解决自动化界面设计中常见的“奇数边距混乱、圆角挤压变形、盲目调色砸出突兀灰脏补丁、规范自相矛盾导致数值死锁”等工程痛点。

---

## 一、 空间几何常数与间距语义化架构

本系统严禁在组件内部硬编码散落的像素数值，所有间距必须遵循**“M3 百进制标尺 $\to$ 关系几何语义指针 $\to$ 组件零像素消费”**三层解耦。

### 1. M3 百进制空间量子标尺 (Baseline Quantum Scale)
以 **8px 为系统基准量子**（$1.0\times = 8\text{px} = \text{space-100}$），底层仅提供严格整除的离散常数池，严禁出现奇数或 Subpixel 浮点数：

```css
:root {
  --space-25:  2px;   /* 0.25x: 极限微调、发丝线对齐 */
  --space-50:  4px;   /* 0.50x: 原子微间隙、图标与文字内联 */
  --space-75:  6px;   /* 0.75x: 紧凑型输入框与标签微补 */
  --space-100: 8px;   /* 1.00x: 系统基准量子 (Base Unit) */
  --space-150: 12px;  /* 1.50x: 控件内衬、次级卡片内隙 */
  --space-200: 16px;  /* 2.00x: 标准卡片间隙 (Grid Gap)、内容段落垂直流 */
  --space-300: 24px;  /* 3.00x: 容器标准内边距 (Padding)、卡片领地缓冲 */
  --space-400: 32px;  /* 4.00x: 独立功能区块间距、页面子模块分界 */
  --space-600: 48px;  /* 6.00x: 页面级大外壳留白、主段落分界 */
}
```

### 2. 关系几何与语义插槽 (Relational Geometry Slots)
落实格式塔知觉心理学 4 大关系定律，全站组件**仅允许引用以下 8 个语义插槽**：

| 语义插槽 (Token) | 默认装配值 | 对应的格式塔法则与物理含义 |
| :--- | :--- | :--- |
| `--gap-atomic` | `var(--space-50)` (4px) | **定律 1：原子强内聚**。图标+文字、Badge 微标签内部。 |
| `--gap-sibling` | `var(--space-100)` (8px) | **定律 1：兄弟弱相关**。标题+正文、输入框 Label+Input。 |
| `--gap-flow` | `var(--space-200)` (16px) | **定律 1：并列流向**。卡片并列 Gap、正文段落纵向间距。 |
| `--pad-control-y` | `var(--space-75)` (6px) | **定律 2：控件垂直内衬**。按钮、输入框垂直内边距。 |
| `--pad-control-x` | `var(--space-150)` (12px) | **定律 2：控件水平内衬**。按钮、输入框水平内边距。 |
| `--pad-card-y` | `var(--space-200)` (16px) | **定律 2 & 3：非对称领地**。垂直缓冲（压缩优先区）。 |
| `--pad-card-x` | `var(--space-300)` (24px) | **定律 2 & 3：领地包容**。水平缓冲（保证 $\text{Padding} \ge \text{Internal Gap}$）。 |
| `--gap-section` | `var(--space-400)` (32px) | **定律 4：图底呼吸底线**。跨功能独立大区块分隔。 |
| `--pad-shell` | `var(--space-400)` (32px) | **定律 4：页面大外壳留白**。页面容器主内衬。 |

> [!CAUTION] 组件层零像素原则 (Zero-Pixel in Components)
> 在各组件选择器（如 `.card`, `.btn`, `.input`）内部，**绝对禁止出现具体的 `16px`、`24px` 等硬编码像素字样**；必须全量绑定语义插槽。

### 3. 圆角系统标尺与同心嵌套法则 (Radius Scale & Concentric Nested Radius)
为保证整页视网膜级平滑连续，圆角同样纳入系统标尺：

```css
:root {
  --radius-xs: 4px;                       /* 微弧保底（同心公式下限） */
  --radius-sm: 8px;                       /* 控件：按钮、输入框 */
  --radius-md: 12px;                      /* 紧凑卡片、二级抽屉 */
  --radius-lg: 16px;                      /* 标准卡片外层 */
  --radius-xl: 20px;                      /* 舒展卡片、模态弹窗 */
  --radius-card:    var(--radius-lg);     /* 卡片外层语义映射 */
  --radius-control: var(--radius-sm);     /* 控件外层语义映射 */
  --radius-pill:    999px;                /* 药丸型 Badge / 标签 */
}
```

* **几何定理**：当一个带圆角的子元素嵌套在带圆角的父容器中时，为保持视觉边距厚度均匀，内外圆角必须同心：
  $$R_{\text{inner}} = \max(R_{\text{outer}} - \text{Padding}, \text{保底微弧 } 4\text{px})$$
* **下沉声明铁律（防作用域求值固化）**：
  * **严禁在 `:root` 声明静态复合衍生变量**（如 `--radius-inner: calc(...)`）；
  * **必须直接将原生数学公式注入被嵌套组件的选择器属性上**：
    ```css
    .nested-element {
      /* 原生表达式下沉：动态捕获局部生效的 Padding 与父级圆角 */
      border-radius: max(var(--radius-xs), calc(var(--radius-card) - var(--pad-card-x)));
    }
    ```

### 4. 运行时密度调度 (Density Modifiers)
系统通过 CSS 属性选择器的树状作用域就近覆盖，实现全局或局部容器的一键密度缩放，无需 JS 介入，杜绝半像素模糊：

```css
/* Level -1: 紧凑档位 (Compact) - 垂直轴定向等差压缩 4px，微间隙触底保底 */
[data-density="compact"], [data-density="-1"] {
  --radius-card: var(--radius-md);  /* 卡片圆角收缩至 12px */
  --gap-atomic:  var(--space-50);   /* 4px 触底保底 */
  --gap-sibling: var(--space-75);   /* 6px */
  --gap-flow:    var(--space-150);  /* 12px (-4px delta) */
  --pad-card-y:  var(--space-150);  /* 12px (-4px vertical compression) */
  --pad-card-x:  var(--space-200);  /* 16px (-8px horizontal compression) */
  --gap-section: var(--space-300);  /* 24px (-8px delta) */
  --pad-shell:   var(--space-300);  /* 24px */
}

/* Level +1: 舒展档位 (Spacious) */
[data-density="spacious"], [data-density="1"] {
  --radius-card: var(--radius-xl);  /* 卡片圆角放大至 20px */
  --gap-atomic:  var(--space-75);   /* 6px */
  --gap-sibling: var(--space-150);  /* 12px */
  --gap-flow:    var(--space-300);  /* 24px */
  --pad-card-y:  var(--space-300);  /* 24px */
  --pad-card-x:  var(--space-400);  /* 32px */
  --gap-section: var(--space-600);  /* 48px */
  --pad-shell:   var(--space-600);  /* 48px */
}
```

* **容器高度弹性原则**：严禁在带 Padding 的容器上写固定 `height: xx px`，必须统一采用 `min-height` 或完全交由 `padding + content` 自然支撑。

## 二、 核心色彩与表面安全锁（Surface & Color Defense）

### 本 Skill 的核心立场（立场声明）
1. **APCA 是下限标准（地板），不是美感标准**。“更合规”不等于“更好看”。任何只设下限的指标，执行者与 AI 均会一路加黑到顶，导致大字号承载最重墨量，破坏页面灰度平衡。
2. **文字类指标同时设定严格上限**：一级文字达到要求即停，严禁盲目加黑。
3. **色相、质感、气场与信息密度，终审裁决权 100% 移交人类肉眼**。

### 规范不约束的三个自由变量与反向耦合
明度（Luminance $Y$）是唯一被对比度算法计算的物理量。以下三个变量在 APCA 与 WCAG 算法中**完全不消耗对比度成本**，应作为拉开层级的主力：
1. **色相与彩度 (Hue & Chroma)**：不同色相在相同明度下具有相同的合规度，但能传递清晰的功能心理语义。
2. **字重 (Font Weight)**：字重从 400 提升至 700 时，对比度完全不变，但在人眼中能瞬间建立清晰层级。
3. **留白与负空间**：适当收紧或放开留白，即可重塑呼吸感，无需改动对比度。
4. **字号反向耦合原则**：APCA 遵循人眼空间频率生理特性——**字号越大，感知越敏锐，所需对比度越低**。因此系统确立默认手法：**“大字调淡、小字深墨”**，绝不在大号标题上堆积最深墨色。

```
       【输入待治理界面 / 粗糙原型】
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【阶段一：定纸 (Surface Freeze)】                      │
│ 确立底板与主卡片，剔除脏灰色块；静态表面锁定 ΔL* <= 3   │
└───────────────────────┬────────────────────────────────┘
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【阶段二：调墨 (Text Tuning / APCA & 场景分诊)】       │
│ 纸张绝对不动，依据用途分诊调控文字明度与字重           │
└───────────────────────┬────────────────────────────────┘
                        │
                        ▼
┌────────────────────────────────────────────────────────┐
│ 【阶段三：控件与焦点核验 (Control & Focus)】           │
│ 控件文本满足 Lc >= 60；保留标准化 :focus-visible 轮廓线 │
└────────────────────────────────────────────────────────┘
```

### 防线 1：调墨不调纸（Text First / Surface Freeze）
* **病理原理**：文本像素覆盖率 $< 5\%$，调整文本明度对全屏灰度平衡近乎零冲击；而重涂大面积背景色（覆盖率 $> 60\%$）会瞬间摧毁页面的产品调性、视觉极性与整体光感。
* **刚性执行顺序**：
  1. **先定纸**：底盘与主卡片背景色一旦确立（体现产品核心调性），**100% 绝对冻结**；
  2. **后调墨（调整文本属性）**：当检测到文本可读性不满足规范时，**严禁通过改动卡片底色或擅自添加背景色块来凑对比度**；必须在冻结的底盘上，通过调整文本自身的属性（颜色 Token、字号、字重）达成标准。

### 防线 2：静态表面低 Delta 约束（Low Delta Surfaces, $\Delta L^* \le 3$）
* **定义与量化口径**：
  * **本规则严格约束“静态大面积布局容器（Surfaces）”**，包括主底板、工作台大岛、内容卡片与分栏面板；
  * 明度差量化为 **CIE $L^*$ 绝对差值**：浅色模式下，嵌套卡片、内部面板与主背景之间的明度差 **$|L^*_{\text{surface}} - L^*_{\text{base}}| \le 3$**（深色模式下阈值放宽至 $\le 5$）；
  * **突兀脏灰处置原则**：若原卡片背景为中度脏灰（如 `#d1d5db`），**默认一律提亮升档至纯白 `#ffffff`**（此时 $\Delta L^*$ 降至 $\le 2$ 满足规范）。仅在无法拉开空间呼吸感时，方退回采用发丝线边界。
* **交互控件（Controls）与主按钮豁免条件**：
  * 按钮、Badge、输入框属于实体交互构件，**不属于大面积静态表面，不受 $\Delta L^* \le 3$ 约束**；
  * **主操作按钮（Primary Action）**：允许使用深色实底，前提是其为所在卡片/视图区域内的**全屏唯一最高层级操作焦点**，且其投影面积不得超过所在卡片面积的 **12%**；
  * **Badge 多重身份**：实心填充 Badge 按交互控件处理（文字对 Badge 背景实测满足 $L_c \ge 60$）；描边/无背景 Badge 严格按用途分诊归入文字层级治理。

### 防线 3：静态边界界定优先与交互焦点保护（Static Separation & Focus Freeze）
* **静态容器界定优先次序**：
  1. **首选**：大尺度负空间留白（`gap: var(--gap-flow)` 或 `var(--gap-section)`）；
  2. **次选**：符合设计系统的 1px 低透明度微发丝线；
  3. **绝对禁止**：依靠高对比度的深浅大色块强行拼接容器。
* **保留交互聚焦轮廓线（Focus Indicator Protection）**：
  * **严禁消除交互聚焦轮廓**：交互控件在 `:focus`、`:focus-visible` 状态下必须保留清晰可见的键盘聚焦指示轮廓：
    * 轮廓宽度：$\ge 2\text{px}$；
    * 轮廓偏移（offset）：$\ge 2\text{px}$；
    * 轮廓颜色相对相邻背景对比度：$\ge 3:1$；
  * **绝对禁止**在交互控件上使用 `outline: none` 或将其弱化为不可见。

### 防线 4：APCA 场景用途分诊与双轨合规矩阵（APCA 0.1.98G-4g & Dual-Track）
* **标准架构与锁定版本**：
  * **设计期唯一驱动核心**：采用 **W3C APCA (算法版本：0.1.98G-4g)** 作为感知对比度权威判据；
  * **法定合规审计门禁**：若交付项目需通过法定无障碍审计（EN 301 549 / Section 508 / ADA Title II），则以 **WCAG 2.1 AA 4.5:1** 为附加验收门禁（冲突时以外部法定 AA 标准为准）。
  * **算法估算换算锚点**：
    | WCAG 2.x 对比度 | 对应 APCA 估算感知值 | 适用场景说明 |
    | :--- | :--- | :--- |
    | $3:1$ | $\approx L_c 52$ | 控件边界、大号文字、焦点环 |
    | $4.5:1$ | $\approx L_c 67$ | 法定正文文本合规底线 |
    | $7:1$ | $\approx L_c 80$ | 极高可访问性优先场景 |

* **场景用途分诊模型（Use-Case Triage Model）**：
  放弃脱离场景的机械三级切分，按内容使用用途进行工程分诊：

  | 场景用途 | 典型界面内容 | $L_c$ 生理下限 | $L_c$ 上限与执行风控约束 | 字号物理底线 |
  | :--- | :--- | :--- | :--- | :--- |
  | **阅读型** | 标题、卡片正文、说明段落、表单 Label | **$L_c \ge 75$** | **到线即停**：达 $L_c 75$ 即停止加深；**严禁超过 $L_c 90$**（$L_c > 90$ 留给全屏唯一焦点，每屏 $\le 1$ 处） | 推荐 $\ge 14\text{px}$，极限 $\ge 12\text{px}$ |
  | **查阅型** | 数据 ID、时间戳、版本号、路径、代码哈希 | **$L_c \ge 60$** | **交互加深契约**：平时保持 $L_c \ge 60$；**必须配置 Hover 加深至 $\ge 75$ 或点击展开/一键复制**，否则按阅读型处理 | 推荐 $12 \sim 13\text{px}$ |
  | **装饰/失效态** | 输入框占位符 (Placeholder)、Disabled 置灰文案 | **$L_c \ge 45$** | 满足视觉弱化诉求，不设上限；禁止用于传达关键业务信息 | **刚性红线：严禁低于 12px** |

## 三、 三工作模式执行契约

### 模式 1：`--mode=diagnostic`（事前排查 / 截图初评）
* **定位**：纯只读静态分析器。*严禁修改任何业务代码。*
* **输入**：前端代码文件、CSS 样式表，或界面截图。
  * *注：截图输入仅用于空间几何项（间距、圆角）；色彩明度项必须直接提供 CSS 色值输入。若仅有截图，色彩分析结果附带 $\pm 2$ 容差说明。*
* **执行逻辑**：
  1. 扫描盒模型中逃逸出语义 Token 的非标硬编码像素（检查是否违反零像素原则）；
  2. 扫描嵌套卡片内外圆角是否出现同尺寸挤压（检查是否未下沉同心公式）；
  3. 扫描静态大面积表面是否存在明度差超过 CIE $L^* > 3$ 的突兀脏灰实底色块；
  4. 检查各级文本是否满足用途分诊模型（阅读型 $\ge 75$ 且 $\le 90$，查阅型 $\ge 60$，字号 $\ge 12\text{px}$）。
* **输出**：结构化的《空间与表面病灶清单》。

---

### 模式 2：`--mode=patch`（设计执行 / 规范化补丁）
* **定位**：规范化代码重构执行器。在**空间语义化与先墨后纸安全锁**双重约束下产出工程级代码。
* **输入**：确认需要修复布局/表面缺陷的目标文件。
* **执行逻辑**：
  1. **间距与圆角语义化注入**：
     * 在 `:root` 挂载百进制标尺（`--space-25` 到 `--space-600`）、8 大语义插槽以及 `--radius-*` 标尺；
     * 将组件内部所有硬编码像素替换为语义 Token 指针（`--gap-*`, `--pad-*`），实现组件层零像素；
     * 在嵌套组件上直接注入原生同心公式：`border-radius: max(var(--radius-xs), calc(var(--radius-card) - var(--pad-card-x)))`；
     * 挂载 `[data-density="compact"]` 与 `[data-density="spacious"]` 调度规则；
  2. **色彩与表面安全修复**：
     * **定纸**：背景底板与主卡片保持不动（冻结）；中度脏灰色块默认提亮升档至纯白（`#ffffff`），使 $\Delta L^* \le 3$；
     * **调墨**：在冻结纸面上，按用途分诊调控文本 Token 或字重，阅读型达 $L_c 75$ 即停并锁在 $\le 90$，查阅型达到 $L_c \ge 60$，全文字号补齐至 $\ge 12\text{px}$；
     * **控件与焦点**：控件内文本满足 $L_c \ge 60$；添加符合标准的 `:focus-visible` 轮廓线（宽 $\ge 2\text{px}$，偏移 $\ge 2\text{px}$，对比度 $\ge 3:1$，严禁 `outline: none`）。
* **交付物**：直接交付重构后的完整目标文件（必要时可附 Git 差异对比）。

---

### 模式 3：`--mode=verification`（事后审查 / 终审门禁）
* **定位**：交付前客观硬红线闸门与只读数据辅助。
* **执行逻辑**：静态走查以下硬伤：
  * [ ] 组件内部是否违规残留非 Token 硬编码间距像素（组件零像素机检）；
  * [ ] 嵌套组件是否正确下沉了同心圆角动态公式（严禁内外同大角）；
  * [ ] 容器高度是否弹性化（严禁写死 `height` 导致密度压缩被截断）；
  * [ ] 静态大面积表面是否满足明度差 CIE $|L^*_{\text{surface}} - L^*_{\text{base}}| \le 3$（深色模式 $\le 5$）；
