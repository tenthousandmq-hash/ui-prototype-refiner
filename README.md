# UI 原型增量规整流水线 (UI Prototype Refiner)

专为设计师打造的**增量原型快速工业化流水线**。

---

## 一、 解决的核心场景与痛点

在敏捷产研流程中，设计师往往无法全程介入每个增量功能，常见现象为：**产品经理（PM）使用基础组件快速拼装原型页面，直接进入评审或交付研发**。此类原型虽具备业务功能，但在细节上普遍存在“毛坯感”：
* 图标乱用（emoji 占位、线宽不一、非标尺寸）；
* 排版压迫（行宽拉通全屏、行高过紧、汉字成团）；
* 间距失范（手写 7px/13px/15px 奇数边距，未对齐网格）；
* 表面粗糙（文本发灰看不清、边框生硬黑粗）。

**本流水线的目标**：在**绝对不动核心业务骨架与交互动线**的前提下，一键接管机械化微调脏活，秒级将原型代码拉升至 **75~80 分的工业级规范界面**，直接可供研发投产。

---

## 二、 两种标准输入物

1. **评审过的原型截图（图片）**：PM 拼装的原型视口截图；
2. **存量 HTML 结构（代码）**：已有初步结构但样式粗糙的 HTML/组件文件。

---

```
        │
        ▼

│ 2. 只读扫描 4 类机械硬伤 (图标/排印/网格/表面)          │

                        ▼
┌────────────────────────────────────────────────────────┐

│ • 后台网格: 4px 乘数吸附 / 嵌套同心圆角                 │
│ • 后台图标: 清除 emoji，批量替换为 16px/20px 标准 SVG   │
│ • 色彩安全锁: 坚守【调墨不调纸】，大面积底色绝对冻结     │

                        ▼
┌────────────────────────────────────────────────────────┐
│ Step 3: 交付规整代码、变量对照表与切片 (Deliver & Review)│

│ 3. 变量变更对照表 (Token Diff Matrix)：显式对账修改明细   │
└────────────────────────────────────────────────────────┘
```

## 五、 刚性安全防线（杜绝负向劣化）

1. **绝对承重墙锁定**：禁止擅自删除原型中已存在的任何字段、输入框、表头或操作按钮；
2. **色彩安全锁（调墨不调纸）**：
   * 遇到文字读不清或对比度不足时，**严禁通过调亮/调暗大面积容器背景来凑对比度**（杜绝画面产生突兀黑脏色块）；
   * 仅允许压低前景文字 Token 明度，底板背景绝对冻结；
3. **留白优先原则**：边界界定优先依靠 16~24px 负空间留白或 1px 半透明发丝线（`rgba(0,0,0,0.06)`），严禁用大色块硬拼。
