# UI 原型增量规整流水线 (UI Prototype Refiner)

专为设计师打造的**增量原型快速工业化流水线**。

---

## 一、 解决的核心场景与痛点

在敏捷产研流程中，设计师往往无法全程介入每个增量功能，常见现象为：**产品经理（PM）使用基础组件快速拼装原型页面，直接进入评审或交付研发**。此类原型虽具备业务功能，但在细节上普遍存在“毛坯感”：
* 图标乱用（emoji 占位、外挂 PNG 位图、线宽不一、非标尺寸）；
* 排版压迫（行宽拉通全屏、行高过紧、汉字成团、半像素虚化）；
* 间距失范（手写 7px/10px/14px 奇数边距，未对齐网格）；
* 表面粗糙（文本发灰看不清、边框生硬黑粗、层级粘连）。

**本流水线的目标**：在**绝对不动核心业务骨架与交互动线**的前提下，一键接管机械化微调脏活，秒级将原型代码拉升至 **75~80 分的工业级规范界面**，直接可供研发投产。

---

## 二、 两种标准输入物

1. **评审过的原型截图（图片）**：PM 拼装的原型视口截图；
2. **存量 HTML 结构（代码）**：已有初步结构但样式粗糙的 HTML/组件文件。

---

## 三、 三步直通作业流 (3-Step Pipeline)

```
[PM 原型图 / HTML]
        │
        ▼
┌────────────────────────────────────────────────────────┐
│ Step 1: 锁骨架，抓病灶 (Lock & Scan)                    │
│ 1. 业务实体承重墙全量锁定 (字段、按钮一个不删)           │
│ 2. 只读扫描 4 类机械硬伤 (图标/排印/网格/表面)          │
└───────────────────────┬────────────────────────────────┘
                        ▼
┌────────────────────────────────────────────────────────┐
│ Step 2: 物理级参数校准 (Direct Calibration)            │
│ • 后台排印: 锁 65ch / 行高 1.6 / 整数阶梯 (禁半像素)    │
│ • 后台网格: 4px 乘数吸附 / 嵌套同心圆角                 │
│ • 后台图标: 清除外挂位图，装配 16px/20px 内联 SVG      │
│ • 色彩安全锁: 坚守【调墨不调纸】，大面积底色绝对冻结     │
└───────────────────────┬────────────────────────────────┘
                        ▼
┌────────────────────────────────────────────────────────┐
│ Step 3: 严格按输出模板交付 (Deliver & Review)           │
│ 1. 变更对照表 (Token Diff Matrix)：显式对账修改明细   │
│ 2. APCA 感知阶差核算 (三级梯度与底线核验)               │
│ 3. 交付前自检门禁勾选 (4 项硬伤逐一消灭)                │
│ 4. 自包含、零外部断链风险的规范 HTML/CSS 代码          │
└────────────────────────────────────────────────────────┘
```

---

## 四、 刚性交付输出模板（Output Schema Lock）

为确保跨 Agent（Antigravity、Codex、Cursor、Claude Code 等）执行时标准不漂移、不偷工减料，流水线要求模型**必须按以下 4 模块结构模板输出**：

1. **【Token 变更对照表 (Diff Matrix)】**：显式说明所有修改项及物理纠偏依据；
2. **【APCA 感知阶差核算】**：核算 Primary $\to$ Secondary $\to$ Tertiary 阶差及底线；
3. **【交付前反思自检门禁】**：在输出代码前逐一勾选确认（图标纯矢量内联、4px 模数、无半像素、65ch 黄金视宽）；
4. **【规整后代码】**：完整可投产代码，自包含纯线内联 SVG，无任何外部资产破链风险。
